
# CH3实验报告

## 一、本实验实现功能

实现系统调用`sys_trace`，功能根据传入的`trace_request`不同有如下三种功能：

1. `trace_request == 0`，从用户地址`id`读取一个字节；
2. `trace_request == 1`，向用户地址`id`写入一个字节`data`；
3. `trace_request == 2`，统计系统调用的调用次数，包含当前调用；
4. 其他情况，将`-1`作为返回。

实现重点在于 `trace_request == 2`的情况，为了避免因为所有权的改变，所有不能传输`times`字段到`syscall`，则直接在为`TaskManager`添加计数功能和获取当前计数的功能并包装到外部使用。

## 二、简答题

1. 理解函数，回答问题使用的版本为`RustSBI-QEMU Version 0.2.0-alpha.2`. 三个程序出错的原因如下：
   1. `ch2b_bad_address.rs`中，将`0x0`作为地址写入数据，不合法，触发`PageFault`
   2. `ch2b_bad_instruction.rs`中，在用户态执行内核态的指令`sret`，触发`IllegalInstruction`
   3. `ch2b_bad_register.rs`中，在用户态访问内核态的寄存器`sstatus`，触发`IllegalInstruction`
2. 深入理解`trap.S`中两个函数`__alltraps`和`__restore`的作用，回答问题
   1. `sp`代表`trap`上下文在内核栈的起始地址。`__restore`可以用于任务切换后的任务恢复和异常处理完成的应用程序恢复。
   2. 特殊处理了`sstatus, sepc, sscratch`寄存器。`sstatus`作为状态寄存器，其SPP字段记录了`trap`前的特权级是U态还是S态。`sepc`确定程序跳转后的地址，存储的是陷入异常前的最后一个指令地址，最后会+4。`sscratch`保存了用户态下的栈指针，用于栈的切换。
   3. `x2`sp,栈指针，不能直接恢复，否则会丢失内核栈信息，需要后续处理。`x4`tp,线程指针，一般用不到。
   4. `sp`指向用户栈上下文，`sscratch`指向内核栈上的Trap上下文。
   5. 状态切换指令是`sret`，它会检查`sstatus`作为状态寄存器，根据SPP字段返回U态，然后根据前面恢复的`sepc`寄存器跳转到用户程序继续执行。
   6. `sp`指向内核栈，`sstatus`指向下用户栈。
   7. 从 U 态进入 S 态是`ecall`指令。
